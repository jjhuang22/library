# Library agent instructions

This repository is the Library. Read README.md for its structure and commands, then docs/publishing.md before creating, queueing, or publishing any artifact. For Acquired companions, also read docs/acquired/authoring.md before writing or revising content.

- Creating an artifact defaults to queueing it on its own `queue/<collection>/<id>` branch. Commit its complete bundle and evidence map and push that queue branch for backup. Do not publish it to main unless requested.
- Interpret an unambiguous “publish [episode]” request as authorization to prepare, check, commit, push, and verify only that episode. Follow docs/publishing.md; use `npm run artifact:publish -- <collection>/<id> --prepare`, browser-check the prepared worktree, then use `--push`. Never merge a combined queue branch into main.
- For Acquired, first find and read the full transcript on the official Acquired episode website, including its Transcript tab or linked transcript view, plus official corrections. Do not ask the user to copy/paste a transcript that can be retrieved there. Follow the authoring guide's documented fallback when the full official text cannot be retrieved; show notes and bibliographies are not transcripts.
- Keep permanent evidence maps concise under `docs/evidence/<collection>/<id>.md`. Record source passages, corrections, qualifications, and timing provenance, not temporary paths, agent handoffs, or test logs. Keep maps for every published and completed queued artifact centrally on main, with the matching map also on its queue branch. Run `npm run evidence:check`. Planned episodes without an artifact do not need a map. Do not fabricate a retrospective audit for legacy artifacts.
- Keep each deployable artifact in `public/artifacts/<collection>/<id>/`, with `index.html` and its own images. Shared Acquired styles and navigation live in `public/assets/acquired/`. Preserve public routes and original creation dates.
- Hosting is GitHub → Vercel at `jjhuang22/library`: a push to main builds with `npm run build`, output `dist/`. Preserve the existing audience and hosting project. Do not use ChatGPT Sites or another deployment project. Check Vercel's commit status and the live URL; distinguish deployment success from a blocked live check.
- Prefer this repository over the older `/workspace/acquired` checkout. Preserve other queued work and unrelated changes. Do not force-push, delete queue/archive branches, or publish other episodes as part of a selective publication.
